Software engineers are not hired to write a program; we are hired to engineer a solution that comes in the form of software. Engineering skills still matter in the age of AI.

Will AI take my job? I don't know. As engineers, we are hired to solve a problem. We are hired to make decisions and be responsible for them. AI does not do this. "A computer can never be held accountable. Therefore a computer must never make a management decision," reads a famous quote.

Engineering skills are still relevant. How can you tell that AI is producing a program that does only what you want—not more—if you don't know how to program? How can you tell that the program is not storing passwords using archaic algorithms; is not relying solely on frontend validation; or is using the most efficient algorithm for the task? How do you even tell that these aspects exist in the first place?

Recently I let Claude find a bug in the code. I let it do what it was best at: understanding texts. It did the job thoroughly and found a possible cause, but it didn't make sense to me so I had to give it my assumption, to "steer" it. Finally the root cause was identified. I'm mentioning this because it shows that AI can be stuck in its echo chamber, so there needs to be someone who can ask the right question. AI helps engineers do tedious tasks quicker, because they know what questions to ask.

When you learn programming, you don't only learn to talk to computers, but also to think systematically. A software engineer is neither a Golang engineer, a JavaScript engineer nor a C engineer, rather an engineer who utilises their tools to build a solution. AI is part of the toolbox. It is never out of style to learn programming; it is never in.

To me, programming is craftwork. Machines never lie. Bits and bytes never betray. The computer is a reflection of an engineer's precision: it only does what you tell it to. This fascination makes me see programming as craftwork, not as a task.

Surely the landscape will change, but AI is not the silver bullet.
